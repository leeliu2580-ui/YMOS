# 加密观察台 MVP 需求文档

## 1. 项目定位

本项目是 `YMOS` 体系下的一条加密投研支线，目标不是做一个会自由发挥的“自动研究员”，而是做一个服务于个人持仓决策的 **加密观察台**。

它优先解决 5 类高频问题：

1. 这个币最近强不强，价格结构怎么样？
2. 协议资金有没有回来，TVL 是增强还是走弱？
3. 官方最近有没有公告、治理、合作、产品变化？
4. K 线是在趋势里、震荡里，还是已经走坏？
5. 结合我的开仓价和仓位，现在该继续看、减仓，还是先观察？

本项目默认遵循：

- 先脚本，后总结
- 先事实，后判断
- 无数据，不编造
- 高内聚，低耦合

本项目必须延续 `YMOS` 原有的暗号路由习惯，不单独发明一套新的主交互语言。

---

## 2. 设计目标

### 2.1 MVP 目标

在不破坏现有 `YMOS` 结构的前提下，为加密标的补充一套最小可用工作流，覆盖以下 5 个模块：

1. `价格与TVL跟踪`
2. `官方信息跟踪`
3. `K线观察`
4. `仓位复盘`
5. `事件核验`

### 2.2 成功标准

本期 MVP 的成功，不是“能聊几句加密”，而是：

1. 能复用 `YMOS` 现有暗号风格触发工作流
2. 能优先调用脚本获取价格、TVL、公告、K 线等确定性数据
3. 在有数据时输出结构化结果，在无数据时明确返回“暂无数据 / 获取失败 / 待人工补充”
4. 不编造任何价格、TVL、公告、K 线、仓位相关事实
5. 输出结果可落盘、可复盘、可重复执行

### 2.2.1 暗号与触发方式

本期 MVP 必须优先兼容 `YMOS` 既有暗号习惯，不另发明一套新的主交互语言。

支持以下核心暗号：

#### A. 调研类暗号

- `调研一下 [TICKER]`
- `调研一下 [项目名]`

适用场景：

- 用户第一次系统性查看一个加密标的
- 用户希望拿到一个较完整的观察快照

内部执行要求：

1. 优先读取 `持仓与关注/加密观察清单.md`
2. 调用脚本获取该标的：
   - 价格数据
   - TVL 数据
   - 官方信息
   - K 线结构
   - 可选的高质量投研链接
3. 聚合为统一项目快照
4. 再由 Agent 按 `Eyes` / `Brain` 的要求输出研究摘要

输出目标：

- 价格与 TVL 快照
- 官方信息摘要
- K 线结构摘要
- 当前观察重点
- 待补充信息项

#### B. 持仓复盘类暗号

- `持有怎么看 [TICKER]`
- `持仓 [TICKER] 怎么看`

适用场景：

- 用户已经持有该标的
- 用户希望结合成本、仓位、现状做复盘

内部执行要求：

1. 从 `持仓_状态机.md` 或对应标的文件夹读取持仓信息
2. 调用脚本获取最新：
   - 价格
   - TVL
   - 官方更新
   - K 线
3. 若有仓位成本、仓位价值，则必须先计算浮盈浮亏
4. 再生成标准仓位复盘报告

输出目标：

- 当前仓位状态
- 浮盈浮亏
- 继续持有前提
- 失效条件
- 当前结论

#### C. 单项观察类暗号

- `查一下价格 [TICKER]`
- `看一下 TVL [TICKER]`
- `看一下公告 [TICKER]`
- `看一下 K线 [TICKER]`

适用场景：

- 用户只关心一个单项，不需要完整复盘

内部执行要求：

- 直接调用对应脚本
- 不做多余推理
- 返回结构化结果 + 简短说明

输出目标：

- 单项数据结果
- 数据时间戳
- 数据源
- 若失败，明确标记失败原因

#### D. 事件核验类暗号

- `核验一下 [事件描述]`
- `帮我看看 [项目名] 这件事是真的假的`

适用场景：

- 市场上有争议说法
- 用户想知道某个事件是否可信

内部执行要求：

1. 优先调用脚本获取已有公开数据
2. 再结合官方信息和高质量投研链接做证据整理
3. 若证据不足，必须输出“不足以下结论”

输出目标：

- 已确认事实
- 未确认部分
- 证据来源
- 可信度判断
- 对持仓是否有实际影响

### 2.2.2 暗号与模块映射

| 暗号 | 主要模块 | 是否调用脚本 | 是否允许 Agent 判断 |
|:---|:---|:---|:---|
| `调研一下 [TICKER]` | Eyes + Brain | 是 | 是 |
| `持有怎么看 [TICKER]` | Brain | 是 | 是 |
| `查一下价格 [TICKER]` | Eyes | 是 | 否，默认仅摘要 |
| `看一下 TVL [TICKER]` | Eyes | 是 | 否，默认仅摘要 |
| `看一下公告 [TICKER]` | Eyes | 是 | 否，默认仅摘要 |
| `看一下 K线 [TICKER]` | Eyes | 是 | 否，默认仅摘要 |
| `核验一下 [事件]` | Brain | 是 | 是 |

### 2.2.3 成功验收案例

以下输入必须可被系统正确理解并触发对应流程：

- `调研一下 PENDLE`
- `持有怎么看 PENDLE`
- `查一下价格 PENDLE`
- `看一下 TVL PENDLE`
- `看一下公告 PENDLE`
- `看一下 K线 PENDLE`
- `核验一下 PENDLE 把 BTC 仓位从 67% 降到 22% 这件事`

### 2.3 硬约束原则

#### 2.3.1 脚本优先

凡是价格、TVL、公告、K 线、链接抓取、结构化整理这类确定性任务，必须优先使用脚本完成。

禁止以下行为：

- 明明可以脚本获取，却直接让 Agent 凭网页内容自由发挥
- 明明需要结构化字段，却只输出自然语言段落
- 明明是高频重复流程，却不沉淀成可复用脚本

#### 2.3.2 无数据不编造

这是本项目的最高优先级约束之一。

当脚本无法获取价格、TVL、公告、K 线或其他事实数据时，系统必须明确输出以下之一：

- `暂无数据`
- `获取失败`
- `数据源不可用`
- `待人工补充`
- `不足以下结论`

绝对禁止：

- 猜测价格
- 猜测 TVL
- 杜撰公告内容
- 用旧数据冒充新数据
- 将推测包装成事实

#### 2.3.3 高内聚低耦合

模块必须保持高内聚、低耦合：

- `Eyes/scripts/` 只负责取数、清洗、落盘
- `Eyes/SOP_*.md` 只负责观察报告生成
- `Brain/SOP_仓位复盘.md` 只负责仓位复盘
- `Brain/SOP_事件核验.md` 只负责事件核验
- `持仓与关注/` 只负责真相源和状态维护

禁止以下耦合：

- 价格脚本直接输出仓位建议
- TVL 脚本直接写结论型 Markdown
- 事件核验模块偷偷修改持仓状态机
- 多个脚本共享隐式状态而不落盘

#### 2.3.4 原始数据与解释分离

所有脚本先输出 JSON 原始结果，再由 SOP 或 Agent 生成 Markdown 解释。

要求：

- 原始数据必须可追溯
- 报告结论必须能回指到原始数据
- 结构化结果与自然语言分析分层存放

#### 2.3.5 单点失败不拖垮整体流程

- 单一数据源失败时，允许该字段为空
- 单一脚本失败时，不应导致所有标的全部中断
- 失败必须显式记录原因

## 3. 非目标

本期 MVP 明确不做以下内容：

- 不做自动交易
- 不做下单接口
- 不做全网舆情抓取
- 不做复杂链上归因系统
- 不做多链全覆盖
- 不做完整数据库系统
- 不新增独立顶层 `research/` 目录
- 不替代现有 `持仓_状态机.md`

## 5. 总体工作流

### 5.1 基本执行顺序

所有加密观察任务必须遵循以下顺序：

1. 先识别用户暗号
2. 再调用对应脚本获取结构化数据
3. 再生成统一快照
4. 最后才允许 Agent 做总结、复盘或核验

执行顺序禁止颠倒。

尤其禁止：

- 未获取结构化数据就直接开始分析
- 用推测补足缺失数据
- 跳过脚本直接输出“像是研究报告”的文字

### 5.2 Eyes 层职责

`Eyes` 只负责取数、快照、归档，不负责投资判断。

包括：

- 拉价格
- 拉 TVL
- 拉官方信息
- 拉 K 线关键位
- 生成单标的观察快照
- 归档原始数据和 Markdown 报告

### 5.3 Brain 层职责

`Brain` 只负责两类输出：

- `仓位复盘`
- `事件核验`

### 5.4 持仓与关注层职责

`持仓与关注` 负责维护：

- 要观察的加密标的清单
- 每个标的的基础知识库
- 仓位真相源
- 单标的历史事件和原始数据

## 6. 核心文件需求

## 6.1 `持仓与关注/加密观察清单.md`

### 功能说明

作为加密观察标的的轻量清单，供 `Eyes` 脚本读取，决定今天需要跟踪哪些币。

### 文件格式要求

应使用 Markdown 表格，至少包含以下字段：

- `名称`
- `Ticker`
- `类型`
- `优先级`
- `观察重点`
- `最近更新时间`

### 示例

```md
# 加密观察清单

## Active

| 名称 | Ticker | 类型 | 优先级 | 观察重点 | 最近更新时间 |
|:---|:---|:---|:---|:---|:---|
| PENDLE | PENDLE | 持仓 | A | 价格、TVL、官方更新、BTC 敏感性 | 2026-05-08 |
| HYPE | HYPE | 持仓 | A | 价格结构、平台数据、生态热度 | 2026-05-08 |
| ENA | ENA | Watchlist | B | TVL、激励变化、解锁 | 2026-05-08 |
```

### 验收标准

- AI 能稳定读取表格中的 `Ticker`
- 手工编辑不影响脚本解析
- 至少支持 `持仓` 和 `Watchlist` 两种类型

## 7. Eyes 模块需求

## 7.1 `Eyes/scripts/fetch_crypto_prices.py`

### 功能说明

抓取加密标的价格快照，输出结构化 JSON。

### 输入

- 命令行参数 `--symbols`
- 命令行参数 `--output`
- 可选参数 `--vs btc,eth` 用于相对强弱比较

### 输出

输出 JSON 文件，每个标的至少包含：

- `symbol`
- `price_usd`
- `change_24h`
- `market_cap`
- `volume_24h`
- `vs_btc_strength`
- `vs_eth_strength`
- `timestamp`
- `source`

### 行为要求

- 优先使用可免费获取的稳定来源
- 若主数据源失败，应回退到备用来源
- 输出必须统一字段名
- 不允许只输出自然语言文本

### 验收标准

- 输入 `PENDLE,BTC,ETH` 时能生成合法 JSON
- 字段完整
- 失败时给出明确错误信息
- 不因单个标的失败导致整体崩溃

## 7.2 `Eyes/scripts/fetch_tvl_metrics.py`

### 功能说明

抓取协议 TVL 及相关指标快照。

### 输入

- 命令行参数 `--protocols`
- 命令行参数 `--output`

### 输出

输出 JSON 文件，每个协议至少包含：

- `protocol`
- `tvl_usd`
- `tvl_change_1d`
- `tvl_change_7d`
- `chain_breakdown`
- `main_pools`
- `timestamp`
- `source`

### 行为要求

- 优先使用结构化协议数据源
- 若拿不到细分池数据，可允许 `main_pools` 为空数组
- 不允许把 HTML 直接原样落盘当结果

### 验收标准

- 对 `PENDLE` 能输出结构化 TVL 快照
- 支持 1d 和 7d 变化字段
- 允许部分字段缺失，但必须保留统一 schema

## 7.3 `Eyes/scripts/fetch_official_updates.py`

### 功能说明

聚合官方信息，包括官网公告、博客、治理、官方账号更新。

### 输入

- 命令行参数 `--project`
- 命令行参数 `--output`

### 输出

输出 JSON 文件，结构建议如下：

- `project`
- `items`

每个 `item` 至少包含：

- `title`
- `url`
- `source_type`
- `published_at`
- `summary`
- `confidence`

### 行为要求

- 只抓官方或高可信来源
- 不能把普通媒体文章误标为“官方”
- `source_type` 至少区分：
  - `blog`
  - `governance`
  - `official_social`
  - `announcement`

### 验收标准

- 能输出统一格式
- 每条内容有链接和时间
- 抓不到内容时返回空数组，不报错退出

## 7.4 `Eyes/scripts/fetch_research_links.py`

### 功能说明

抓取高质量第三方投研链接，作为补充阅读材料。

### 输入

- 命令行参数 `--project`
- 命令行参数 `--output`

### 输出

JSON 文件，每项至少包含：

- `title`
- `url`
- `source`
- `published_at`
- `why_relevant`

### 行为要求

- 不抓低质量搬运号
- 只保留高相关、可信来源
- 这是辅助模块，不允许阻塞主流程

### 验收标准

- 失败时不影响其他脚本
- 输出格式统一
- 能单独执行

## 7.5 `Eyes/scripts/fetch_kline_levels.py`

### 功能说明

生成 K 线关键位和结构判断所需的结构化数据。

### 输入

- 命令行参数 `--symbols`
- 命令行参数 `--output`

### 输出

JSON 文件，每个标的至少包含：

- `symbol`
- `timeframe`
- `current_price`
- `support_levels`
- `resistance_levels`
- `trend_state`
- `range_high`
- `range_low`
- `timestamp`
- `source`

### 行为要求

- 本期 MVP 不要求复杂技术指标
- 只要求能生成“支撑 / 阻力 / 趋势状态”的基础快照
- `trend_state` 至少支持：
  - `uptrend`
  - `range`
  - `downtrend`
  - `unclear`

### 验收标准

- 输出可被 Markdown 报告直接引用
- 至少支持日线视角
- 不依赖图形界面

## 7.6 `Eyes/scripts/build_project_snapshot.py`

### 功能说明

聚合价格、TVL、官方信息、K 线、投研链接，生成单标的统一快照。

### 输入

- `price JSON`
- `tvl JSON`
- `official JSON`
- `kline JSON`
- `research JSON`
- 命令行参数 `--output`

### 输出

统一 JSON，至少包含：

- `project`
- `price_snapshot`
- `tvl_snapshot`
- `official_updates`
- `kline_snapshot`
- `research_links`
- `generated_at`

### 行为要求

- 允许部分输入为空
- 必须保持字段稳定
- 必须适配后续 `SOP_仓位复盘.md`

### 验收标准

- 能把多个脚本结果拼成一个统一快照
- 即使有 1 到 2 个上游数据缺失，也能成功输出

## 7.7 `Eyes/scripts/run_crypto_radar.py`

### 功能说明

读取 `加密观察清单.md`，批量执行当天的观察流程。

### 输入

- `持仓与关注/加密观察清单.md`
- 可选命令行参数 `--only PENDLE,HYPE`

### 输出

为每个标的生成：

- `Eyes/价格与TVL/YYYY-MM/价格与TVL_YYYY-MM-DD.md`
- `Eyes/官方信息/YYYY-MM/官方信息_YYYY-MM-DD.md`
- `Eyes/K线观察/YYYY-MM/K线观察_YYYY-MM-DD.md`
- 对应 `Raw_Data` JSON

### 行为要求

- 按清单逐个执行
- 单个标的失败不影响其他标的
- 支持只跑部分币种

### 验收标准

- 能批量跑
- 有简单日志输出
- 产出文件命名统一

## 8. Eyes SOP 文档需求

## 8.1 `Eyes/SOP_价格与TVL跟踪.md`

### 功能说明

指导 Agent 如何读取价格和 TVL 数据，并生成 Markdown 报告。

### 报告结构要求

```md
# 价格与TVL跟踪 - YYYY-MM-DD

## 标的概览
## 价格表现
## 相对强弱
## TVL变化
## 价量与TVL是否背离
## 今日结论
```

### 验收标准

- 结构固定
- 能引用 `build_project_snapshot.py` 输出

## 9.2 `Brain/SOP_事件核验.md`

### 输入

- 官方信息结果
- 投研链接结果
- 若后续补链上脚本，可扩展证据输入

### 输出

Markdown 报告，路径建议：

- `Brain/加密策略分析/YYYY-MM/YYYY-MM-DD_PENDLE_事件核验.md`

### 报告结构要求

```md
# 事件核验 - YYYY-MM-DD

## 待核验事件

## 证据来源
## 尚未确认部分
## 可信度判断

```

### 行为要求

- 先核验，再解释
- 不允许用猜测替代证据
- 允许输出“不足以下结论”

### 验收标准

- 至少能把事件拆成“已确认”和“未确认”
- 对每条关键结论给出来源

## 14. 错误处理要求

所有脚本都必须遵守以下要求：

- 单一数据源失败时不应导致全流程崩溃
- 必须输出明确错误信息
- 允许部分字段为空，但必须保持 schema 不变
- 不允许 silently fail
- 不允许只在终端打印结果而不落盘
- 不允许把自然语言当结构化结果替代品

## 18. 一句话总结

这不是一个“自动加密研究员”，而是一个嵌入 `YMOS` 的 **加密观察台**：

- `Eyes` 看价格、TVL、官方信息、K 线
- `Brain` 做仓位复盘和事件核验
- `持仓与关注` 维护真相源
- `skills` 封装高频固定流程

目标是先把日常观察和仓位判断做稳，再逐步扩展更复杂的研究能力。
